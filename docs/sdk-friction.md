## Historical MCP contract 0.2 follow-up — October 10, 2026

The later [guide review](mcp-best-practices-review.md) found that the installed v1 SDK still accepts JSON-RPC batches. The local 2025-11-25 endpoint now rejects these before domain work. Zod input-mode schema generation also corrected optional default fields in discovery. A raw Node HTTP request was required for the wrong-Host regression because fetch replaced the supplied Host header. Inspector 2.10.1 passed using its legacy protocol mode; no SDK major-version upgrade was implied.

The installed high-level MCP server validates tool arguments before the custom handler and returns its own text-only validation error. To provide uniform structured recovery for invalid arguments, the server now uses the official SDK's low-level `Server` with `ListToolsRequestSchema` and `CallToolRequestSchema`, explicit Zod input validation, and per-tool output validation. Both result variants sit inside a root object so each advertised output schema remains object-shaped. Real HTTP SDK tests cover discovery and all nine tools; protocol failures are not disguised as successful tool results.

Turbopack could not resolve a `.js` re-export for the new source-only TypeScript contract file. The development route returned 500, causing Playwright's server-readiness check to try starting another server and fail. Changing that re-export to the repository's bundler-compatible extensionless path fixed the production build; the subsequent browser run passed all three tests against the existing development processes. Initial failed startup/build attempts are not counted as passing checks.
