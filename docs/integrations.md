## Proposed Food Ordering SPI adapter

The earlier review of Amazon's [Category SDK overview](https://developer.amazon.com/docs/alexaplus/add-ons/overview-category-sdk.html) placed Food Ordering on the Action path. SayGo has no native registration or SPI adapter. This mapping to the [Food Ordering SPI](https://developer.amazon.com/docs/alexaplus/add-ons/food-ordering-spi.html) identifies possible adapter work; the contracts still need validation against current partner requirements.

| SayGo domain responsibility     | Candidate SPI operation(s)                                     | Unresolved adapter work                                                                          |
| ------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Menu/products/stock             | BatchGetMenuItems, GetMenuItem, GetRestaurantAvailability      | Map menu identifiers, choice model and availability responses exactly                            |
| Initial purchase and cart lines | CreatePurchase, CreateCartItem, UpdateCartItem, DeleteCartItem | Purchase/cart lifecycles, API error semantics, authentication/permission model                   |
| Server quote                    | PreviewPurchase                                                | Required customer permissions/data and canonical price/fulfillment mapping                       |
| Customer-approved submission    | SubmitPurchase                                                 | Native consent/checkout requirements, payment-at-window feasibility and notification permissions |
| Status and cancellation handoff | GetPurchase, SearchOrders, CancelPurchase                      | Supported amendments/cancellation and actual commercial POS acknowledgement                      |

Drive-through lane identity, vehicle detection, shared devices, intercom routing and payment at the window need partner confirmation. Native authentication, permissions, fulfillment/payment mapping, tooling, certification and device/history isolation tests remain open.

The review also consulted: [tool/data design](https://developer.amazon.com/docs/alexaplus/add-ons/mcp-addon-tools-schema-data-design.html), [Alexa+ lifecycle](https://developer.amazon.com/docs/alexaplus/add-ons/mcp-toolkit-client-lifecycle.html). SayGo isolates its own web sessions; Alexa conversation-history handling remains unimplemented.
